# REPO CONTEXT FOR PIPELINE AGENTS

## Project: YT Highlight Queue (user-hosted YouTube download+cut queue)
- `web/`: static frontend (Firebase RTDB client, GitHub Pages/Vercel deploy). App logic in web/app.js (964 lines, vanilla JS).
- `agent/`: Node ESM agent runs on user's PC. Polls Firebase RTDB `requests/{id}` (status=pending), downloads via yt-dlp, cuts via ffmpeg, uploads Drive, emails via nodemailer, notifies via Telegram bot API.
- `ptit-dlib-downloader/`: Chrome MV3 extension that scrapes dlib.ptit.edu.vn FlowPaper viewer → builds PDF via pdf-lib → POSTs to local agent's /dlib/upload endpoint (127.0.0.1:8765 or ngrok tunnel).
- Flow: Web form → Firebase RTDB → agent polls → yt-dlp download → ffmpeg cut (segments "mm:ss - mm:ss") → Drive upload → email + Telegram.

## KNOWN ISSUES (pre-audit, from direct code read)
1. **SECURITY-CRITICAL**: Telegram botToken + chatId + Firebase apiKey hardcoded in web/app.js line 6-20 AND content.js/popup.js (DEFAULT_UPLOAD_API_KEY='ptit-dlib-2026-secret'). Anyone can read these from deployed static site and hijack the bot / spam the queue.
2. **Windows incompat**: agent/processor.js PATH join uses ':' not path.delimiter; killProcessTree uses process.kill(-pid) POSIX-only; dns.setDefaultResultOrder ok; install-service.js systemd-only (no Windows service/task-scheduler support); start.sh bash-only; config.example.json paths /usr/bin/* Linux-only.
3. **LOGIC BUG**: agent/agent.js hashUrl (line 29-40) vs processor.js hashUrl (line 33-46) compute DIFFERENT hashes for same URL (agent.js: origin+pathname+'?v=...', processor.js: 'youtube:'+videoId). agent.js version is dead code / unused but confusing.
4. **LOGIC BUG**: cleanup.js recomputes source hash inline with processor-style hash but for non-youtube URLs 'youtube:undefined' collisions.
5. **LOGIC BUG**: web/app.js normalizeTime('1:00:45-1:01:40') SEP_REGEX splits on '-' INSIDE timestamps? No—SEP_REGEX applied to whole line first, but '-' inside '1:00:45' is fine since timestamps use ':'. But '27:00 - 27:35' with en-dash variants OK. Edge: negative or reversed segments (start > end) NOT validated → ffmpeg cut produces empty/error.
6. **LOGIC BUG**: processor.js isFullDownload when segments empty; retry flow after aria2c failure rebuilds args by index-skipping --downloader/--downloader-args (fragile if args order changes).
7. **RACE**: agent.js processingUrls dedup map: if two pending requests same URL arrive in same poll batch, second is marked 'error' — but user pressed "retry" legitimately. Should queue/chain instead.
8. **agent_status/requests read rules ".read":"true"** exposes ALL users' emails/PII to anyone with DB URL (README instructs this).
9. emailer.js formatDate: 'Hi ${request.name}' — request.name unescaped in HTML email (name is free text from web form → HTML injection in email).
10. dlib-upload-server.js: no rate limit; origin check bypassable with 'chrome-extension://' prefix ANY extension, not just yours.
11. web/app.js requestId = 'req_' + Date.now() → two submissions in same ms collide (overwrite via .set()). Use crypto.randomUUID().
12. spawnAsync detached:true + killProcessTree: on cancel, orphaned yt-dlp/ffmpeg may survive if PID reuse or Windows (no process groups).

## REFACTOR REQUIREMENTS (from user)
- Cross-platform win/linux (path.delimiter, cross-platform process kill, Windows service installer + start.bat, config paths resolution with ~ expansion on both OS)
- Modularization (agent.js is god-file; extract state machine, poller, shutdown; shared hashUrl module single source of truth)
- UI/UX polish (web form)
- Audit + tests (no test infra exists — introduce node --test based tests, zero new heavy deps)
- Prioritize dynamic analysis over static (write runnable tests that FAIL on current bugs, pass after fix — TDD red-green as pipeline expects)
- Keep user-hosted architecture (Firebase RTDB hub unchanged; no server migration)

## TEST STRATEGY
- Use Node's built-in `node --test` (no new deps). Tests live in agent/tests/*.test.js, web tests via node --test on pure-logic modules extracted from app.js (parseSegments, normalizeTime, url hash).
- Test command: node --test agent/tests/ (runs all *.test.js)
- agent modules must be importable with dependency injection (no side-effectful top-level Firebase init in library modules) so tests can import pure logic.
